# Deadlock Arabia

نسخة العمل المحلية: http://127.0.0.1:4173/#items . نراجع التعديلات محليًا أولًا؛ ملفات ZIP السابقة لم تُحدّث ولم يُرفع أي تغيير إلى Netlify.

موقع عربي RTL بطابع noir وذهبي، جاهز للنشر كملفات ثابتة دون تثبيت مكتبات أو بناء. نسخة بيانات 16 أكتوبر 2026: 41 شخصية متاحة، 156 أيتم متجر بمستويات 1–4، 164 قدرة أساسية، وصور محلية. تم استبعاد عناصر المستوى الخامس الخاصة غير القياسية. البيانات والصور من https://api.deadlock-api.com/docs، وحقوق اللعبة والصور لـValve. هذا مشروع جماهيري مستقل.

## التشغيل والنشر

1. فك ضغط `Deadlock-Arabia-deploy.zip`.
2. افتح https://app.netlify.com/drop واسحب المجلد الذي يحتوي `index.html` مباشرة. لا توجد عملية build.
3. لا تختبر بالنقر على HTML عبر file://. للتشغيل المحلي من نسخة المصدر: ثبّت Node.js 22 أو أحدث، وافتح الطرفية داخل مجلد المشروع وشغّل `npm start` ثم افتح http://127.0.0.1:4173 .
4. عند ربط Git بدل Drop: أمر البناء فارغ، Publish directory هو `.`. المسارات تستخدم hash، فلا تحتاج تحويلات SPA.

## تفعيل النشر العام عبر Supabase

الحفظ على الجهاز ومشاركة الرابط يعملان دون إعدادات. الدخول ونشر البلدات للمجتمع يحتاجان مشروع Supabase فعليًا:

1. أنشئ مشروعًا من https://supabase.com/dashboard.
2. افتح SQL Editor ونفّذ `supabase.sql` من نسخة المصدر. الجدول `public.builds` وتفعيله بسياسات RLS: القراءة عامة، الإضافة والحذف لصاحب الحساب فقط. يوجد حد 10 منشورات في الساعة لكل حساب.
3. فعّل Email/Password ضمن Authentication → Providers. أبقِ تأكيد البريد مفعّلًا واضبط SMTP للاستخدام العام، وحدود معدل المصادقة وCAPTCHA بما يناسب الإطلاق.
4. في Authentication → URL Configuration ضع عنوان موقعك النهائي HTTPS في Site URL وأضفه إلى Redirect URLs. أضف http://127.0.0.1:4173 للتطوير عند الحاجة. تعمل استعادة كلمة المرور عبر رابط البريد إلى Site URL.
5. عدّل `config.js` في ملفات النشر ثم أعد رفع المجلد:

```js
window.DEADLOCK_CONFIG = {
  supabaseUrl: 'https://YOUR-PROJECT.supabase.co',
  supabaseAnonKey: 'YOUR-PUBLIC-ANON-OR-PUBLISHABLE-KEY'
};
```

لا تضع `service_role` أو أي secret key في الموقع. المفتاح العام ظاهر في المتصفح عمدًا؛ حماية البيانات تعتمد على RLS. صيغة المفتاح القديم anon متوافقة مع الطلبات الحالية؛ يفضّل استخدام anon JWT من API Keys إن لم يقبل مشروعك المفتاح publishable في Authorization.

هذه ملفات ثابتة: **متغيرات Netlify لا تُحقن تلقائيًا** في `config.js`. إذا خزّنت `SUPABASE_URL` و`SUPABASE_ANON_KEY` في لوحة Netlify، يجب أن تضيف خطوة بناء تولّد config.js، أو تعدّله يدويًا عند النشر عبر Drop. لا يحتاج هذا الإصدار متغيرات VITE أو مفاتيح سرية.

## البيانات والتحديثات

- المصدر: `/v1/assets/heroes` و`/v1/assets/items` و`/v2/patches` على https://api.deadlock-api.com . خلاصة التحديثات تجمع منتديات اللعبة وSteam.
- الأسماء والخصائص والأسعار من API فعلي؛ لا توجد إحصاءات فوز أو منشورات مجتمع وهمية.
- توجد لقطة محلية وصور محلية للعمل إذا تعطل المصدر. الخط الخارجي اختياري مع خط بديل محلي.
- صفحة التحديثات تحاول جلب الخلاصة الحديثة تلقائيًا عند فتح الموقع. إن تعذر ذلك تستخدم اللقطة المحلية. المحتوى يظهر بلغته الأصلية إلى أن نكتب ملخصًا عربيًا مراجعًا.
- زر تحديث البيانات يتحقق من المصدر ويحدّث أسعار العناصر الموجودة وخلاصة التحديثات. الشخصيات الجديدة ومراجعة الشروح وتجديد الصور تحتاج تشغيل `npm run refresh-data` في نسخة المصدر ثم إعادة النشر. لا يوجد جدولة خارجية مفعلة.

## صانع البلدات

- حد 12 أيتمًا فريدًا، مرتبة حسب الشراء. يعرض مجموع **الأسعار الكاملة** للأيتمات المختارة؛ لا يحاكي البيع أو خصم المكونات أو فتح خانات اللعبة.
- تخطيط ترتيب فتح القدرات وترقياتها: أول اختيار فتح، ثم 1 و2 و5 نقاط. يعرض عدد الفتحات ونقاط الترقية، بحد أربعة اختيارات لكل قدرة. هذا مخطط ترتيب، وليس محاكاة مستويات أو توقيت توفر النقاط داخل المباراة.
- تغيير الشخصية يعيد ترتيب القدرات. الحفظ محلي حتى 50 بلدة؛ المسودة تحفظ تلقائيًا. رابط المشاركة يحتوي البلدة نفسها، دون قاعدة بيانات. لا تضع معلومات خاصة في الملاحظات المنشورة أو روابط المشاركة.
- نشر المجتمع يتطلب حسابًا؛ يمكن لصاحب المنشور حذفه. لا يوجد تعديل منشور قائم؛ عدّل البلدة وانشر نسخة جديدة.
- يمكن للمشرف حذف المحتوى المخالف من Supabase. قبل فتحه لجمهور كبير أضف مراجعة محتوى وإبلاغًا ومراقبة إساءة الاستخدام. لا يدّعي المشروع توفير هذه الأدوات.

أداة التحديث لا تستخدم أي خدمة ترجمة. إذا تغير الوصف الإنجليزي، يحتاج الشرح العربي مراجعة ويظهر النص الأصلي بدل استخدام شرح قديم بصمت. توجد قائمة انتظار للمراجعة داخل work/arabic-review-queue.json بعد التحديث.

## الاختبارات

`node --test tests/*.test.mjs` يشغّل اختبارات الأسعار ومشاركة النص العربي والتحقق من البلدات وتسلسل القدرات والبيانات المرفقة. نتائج فحص المتصفح ومحدوديات التحقق في `TEST-REPORT.md`. اختبار Supabase الفعلي يتطلب إعداد المشروع؛ لا توجد بيانات حساب أو مفاتيح مرفقة.

تعديلات المتجر الحالية: ثلاثة أقسام ثابتة Weapon / Vitality / Spirit، وأربع مجموعات مستويات لكل قسم. داخل كل مستوى الترتيب حسب الاسم الإنجليزي. هذا ترتيب واضح قريب من المتجر؛ مطابقة كل خانة مع واجهة اللعبة الحالية تحتاج مقارنة مباشرة. اختيار النوع يعرضه لحاله، والبحث يشمل الاسم وفائدة الأيتم بالعربي.

الشروح العربية للأيتمات والقدرات وملخصات الشخصيات مكتوبة محليًا، بدون ترجمة فورية. `localization.js` يحتوي شرح الـ156 أيتمًا وقاموس المصطلحات، و`ability-copy.js` شروح القدرات، و`hero-copy.js` ملخصات الشخصيات. بعض القدرات يفتقد المصدر وصفها؛ هذه الحالات موضحة بدل اختراع معلومات. القيم تظل من API.

صانع البيلد يحدث الملخص وحالة الاختيار فقط، ويحافظ على عناصر المتجر ومكان التمرير أثناء إضافة الأيتمات. تتوفر معاينة عند تمرير الماوس أو تركيز لوحة المفاتيح، وتفاصيل بالضغط على الكمبيوتر والجوال، واحترام إعداد تقليل الحركة.

المصدر JavaScript/CSS/HTML قابل للتعديل مباشرة. `core.js` للحساب والتحقق، `app.js` للواجهات والاتصال، `style.css` للتصميم، و`data/snapshot.json` للبيانات والترجمات.


## الصورة واختيار الشخصيات والليدربورد

الصورة الرئيسية مولّدة خصيصًا للمشروع ومحفوظة محليًا كـPNG وWebP؛ وصف التوليد في ARTWORK.md. ليست صورة رسمية من Valve. صور الشخصيات والأيتمات وشارات الرانك الفعلية من بيانات اللعبة. اختيار شخصية البيلد نافذة صور وبحث، بدل القائمة النصية الأصلية.

صفحة #leaderboard تعرض أول 100 لاعب للمناطق Europe وAsia وNAmerica وSAmerica وOceania، مع مركز كل لاعب وأكثر شخصياته لعبًا. تحاول جلب البيانات عند الفتح وتستخدم نسخة محلية مؤرخة لكل منطقة عند الفشل. لا يوجد تحديث لحظي مستمر.

عدد القيم والفوز والرانك يُجلب بالبحث عن Steam Account ID أو SteamID64 أو الصيغة [U:1:ID]. لا تستخدم possible_account_ids لربط أسماء المتصدرين؛ المصدر يحذر أن الأسماء غير فريدة. مركز الليدربورد ليس شارة الرانك. إحصاءات القيم تجمع matches_played وwins وtime_played من /v1/players/hero-stats للحساب المحدد، وتعكس المرصود عند المصدر وليس إجمالي حساب Steam المضمون. الرانك من /v1/players/{account_id}/rank، وقد يغيب للحسابات المحمية أو تحديد المستوى.

النسخة المحلية تشمل بيانات ليدربورد حقيقية وقت التجهيز. قد يتعذر الجلب المباشر بسبب CORS أو حدود المصدر أو تعطل الخدمة؛ تظهر حالة الفشل ووقت النسخة المحفوظة. لا توجد بيانات لاعبين وهمية.
